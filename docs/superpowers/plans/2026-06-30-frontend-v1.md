# Phase 8 — Frontend v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Narrow operator dashboard (Vite + React + TypeScript) consuming the existing HTTP API. Adds CORS to `api/` first, then builds the `dashboard/` package.

**Spec:** `docs/superpowers/specs/2026-06-30-frontend-v1.md`

**Tech Stack:** React 19, Vite 6, TypeScript 6, vitest 4.1.9 (dashboard); @fastify/cors (api/)

## Global Constraints

- CORS change limited to `api/src/server.ts` and `api/package.json` (Task 1 only)
- `dashboard/` is a new standalone package — no root package.json, no workspace links to other packages
- `dashboard/` does NOT import from actionflow, agentrunner, policyloop, or api — it is a pure HTTP client
- TypeScript strict mode in both packages — `npx tsc --noEmit` must pass
- `api/` — existing 10 tests must not regress; no new api tests in this phase
- `dashboard/` — `npx vitest run` must pass (settings.test.ts + api.test.ts, ≥8 tests)
- `npm run build` from `dashboard/` must produce a clean Vite build
- No component tests (visual verification via dev server)
- No Tailwind or CSS framework — plain inline styles or minimal CSS is fine

### Task 1: CORS on `api/`

**Files to change:**
- `api/package.json` — add `"@fastify/cors": "^10.0.0"` to dependencies
- `api/src/server.ts` — register cors plugin

**What to do:**

- [ ] **`api/package.json`** — add to `"dependencies"`:
  ```json
  "@fastify/cors": "^10.0.0"
  ```

- [ ] **`npm install`** — run from `api/` to install the new dependency.

- [ ] **`api/src/server.ts`** — add import and registration. The cors plugin must be registered on the root `fastify` instance, **after `setErrorHandler` and before the public/protected scope registrations**:

  ```ts
  import cors from '@fastify/cors'
  // ...
  // after setErrorHandler, before fastify.register(pub) and fastify.register(prot):
  await fastify.register(cors, {
    origin: process.env.CORS_ORIGIN ?? '*',
  })
  ```

  Note: `buildServer` must become `async` to use `await fastify.register(cors, ...)`. Update the return type and function signature accordingly:
  ```ts
  export async function buildServer({ deps, logger = false }: BuildServerOptions): Promise<FastifyInstance>
  ```

  All callers of `buildServer` (test file and bin) must `await` the result.

- [ ] Update `api/src/server.test.ts` — add `await` before `buildServer(...)` calls since the function is now async.

- [ ] Update `api/bin/server.ts` — add `await` before `buildServer(...)`.

**Verification:**
- `npm install` from `api/` — installs @fastify/cors
- `npx tsc --noEmit` from `api/` — clean
- `npx vitest run` from `api/` — still 10 tests pass

### Task 3: Dashboard UI — all five features

**Files to create:**
- `dashboard/src/components/SettingsPanel.tsx`
- `dashboard/src/components/StatusBar.tsx`
- `dashboard/src/components/PolicyRunner.tsx`

**Files to change:**
- `dashboard/src/App.tsx` — full implementation composing all components

**What to do:**

- [ ] **`dashboard/src/App.tsx`** — implement full layout:
  - Holds `Settings` state (loaded via `loadSettings` on mount)
  - Derives `ApiClient` from `{ baseUrl: settings.apiUrl, apiKey: settings.apiKey }`
  - Renders: `<SettingsPanel>`, `<StatusBar>`, `<PolicyRunner>`
  - When settings are saved, updates state and calls `saveSettings`

- [ ] **`dashboard/src/components/SettingsPanel.tsx`** — form with three fields:
  - API URL (text input, default `http://localhost:3000`)
  - API Key (password input)
  - Policy IDs (textarea, one ID per line — split on newline/comma, trim, filter empty)
  - Save button — calls `onSave(newSettings)`
  - Props: `initialSettings: Settings; onSave: (s: Settings) => void`

- [ ] **`dashboard/src/components/StatusBar.tsx`** — shows status of `/live`, `/health`, `/version`:
  - Calls `getLive(baseUrl)`, `getHealth(client)`, `getVersion(client)` on mount and on Refresh click
  - Displays: `● /live ok | ● /health ok | v0.1.0` (or error state if fetch fails)
  - Refresh button triggers re-fetch
  - Props: `client: ApiClient`

- [ ] **`dashboard/src/components/PolicyRunner.tsx`** — policy list with run buttons:
  - Renders one row per policy ID in `settings.policyIds`
  - Each row: truncated ID display + "Run Cycle" button + status chip (pending/running/skipped/succeeded/failed)
  - Clicking "Run Cycle" calls `runCycle(client, policyId)` and shows the result
  - "Last Result" section shows full JSON of the most recently completed run
  - Props: `client: ApiClient; policyIds: string[]`

**Styling:** Inline styles only — no CSS framework, no CSS files. Keep it functional.
