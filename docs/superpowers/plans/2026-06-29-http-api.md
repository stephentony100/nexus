# Phase 7 — HTTP API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a new `api/` package exposing `POST /policies/:id/run-cycle`, `GET /health`, and `GET /version` via Fastify. Auth via `X-Api-Key` header. Policy ID allowlist via `API_ALLOWED_POLICY_IDS`. Thin wrapper around the existing `runPolicyCycle`.

**Spec:** `docs/superpowers/specs/2026-06-29-http-api.md`

**Tech Stack:** TypeScript ESM, Fastify 5, vitest 4.1.9, Node.js

## Global Constraints

- New package at `C:/Users/NT/Desktop/nexus/api/` — no root package.json, standalone like all other packages
- All local TypeScript imports use `.js` extension (ESM)
- `actionflow`, `agentrunner`, `policyloop` source changes are limited to: additive exports only in `policyloop/src/index.ts` (Task 1)
- TypeScript strict mode — `npx tsc --noEmit` must pass in all four packages (actionflow, agentrunner, policyloop, api) after each task
- vitest 4.1.9 — run tests with `npx vitest run` from inside the `api/` directory
- TDD: write the failing test first, verify it fails, then implement
- Auth hook applies to ALL routes including `/health` and `/version`
- `runPolicyCycle` is mocked in tests — no real Sui network calls
- Fastify logger must be `false` in `buildServer` (avoid log noise in tests)
